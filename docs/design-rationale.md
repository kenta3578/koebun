# 設計の根拠

koebun がなぜこの形なのか。コードのコメントから参照される、判断の理由だけを置く。

調査の一次データ（競合の価格・機能の棚卸し・実測ログ）は公開対象ではないので `local_docs/` にある。ここに残すのは「その調査から何を決めたか」だけ。

---

## 1. 二層構造（文字起こし → 整形）

音声入力は 2 段で考える。

```
音声 → [音声認識] 文字起こし → [整形] 書き換え → 挿入
```

この分け方自体は一般的で、有償のディクテーションアプリもほぼ同じ構造を取っている。koebun が違うのは**両方をローカルに置くこと**と、**整形を既定で OFF にしていること**。

整形は体感品質を大きく上げるが、後述のとおり事実を書き換えるリスクを持つ。既定を OFF にして、必要な人だけが ON にする構成にしてある。

---

## 2. 整形は事実を書き換える

このプロダクトで**唯一の致命傷**がここ。整形 LLM に文章を通すと、次の種類の書き換えが起きる。

| 種類 | 例 |
|---|---|
| 数値の改変 | 請求額 `4,217` → `4,270` |
| 意味の反転 | 「メールをチェックする**前に**始めよう」→「チェック**せずに**始めよう」 |
| 固有名詞のブレ | 同じ人名を 3 回読ませて 3 通りの綴りになる |

**どれも見た目が自然なので、読み返しても気づけない。** 数字が 1 桁ずれた見積書、否定と肯定が入れ替わった指示。これが警告なしに挿入されるのが、整形機能の最大の危険。

ここから決めたこと:

- **生テキストを必ず残す**（`HistoryEntry.rawText` は上書きしない）。整形後と突き合わせられなければ、書き換えられたことに気づく手段がない
- **送信プロンプトも残す**（ただし選択テキスト・クリップボードの中身は除く）。整形がおかしいとき、モデルの問題かプロンプトの問題かを切り分けられる
- **整形の前後を機械的に点検する**（`FormatDiff`）。数値・URL・メールアドレスが変わっていたら挿入時に知らせる
- **共通の禁止事項はコード側に固定する**（`Mode.commonRules`）。プロンプトを JSON に外出ししても、禁止事項だけは JSON に置かない——ユーザーの編集ミス 1 つで安全弁が消えるため
- **温度は 0**。同じ発話が毎回違う結果になると、整形を疑う手がかりが消える

---

## 3. 日本語だけに振り切る

多言語対応を捨てて、日本語の誤変換パターン（漢字変換・固有名詞・句読点）に辞書とプロンプトを全振りする。

汎用ツールの「どのアプリでもそこそこ」ではなく、「自分の入力先で確実に」を狙う。`AppleTranscriber` が言語を日本語で固定しているのも、`Mode` のプロンプトが日本語前提で書かれているのもこの判断による。

---

## 4. 挿入は「成功だと確信できたときだけ」成功と言う

Accessibility API では、挿入先の変化を読めないアプリがある（多くの Electron 製アプリ、一部のターミナル、Canvas 描画のエディタ）。「変化が無い」ことは「受け付けなかった」の証拠にならない。

- 判定できないときは `.uncertain` に倒し、**警告色で断定しない**。毎回出る警告は、本当の失敗に気づけなくする
- **挿入できたと確認できなかった結果は捨てない**。HUD に残し、クリップボードにも残す（設定で選べる）。結果を失わせないことが、表示の設定より優先
- 変化の量が挿入しようとした量と釣り合うときだけ成功と断定する

---

## 5. 状態は常に見えている

音声入力は「今どの状態か」が分からないと使えない。メニューを開かないと分からないのでは遅い。

- メニューバーアイコンを**形と色の両方**で状態に対応させる（読込中／待機／録音中／処理中／完了／警告）。色が読めない環境でも形で区別できる
- 録音中は HUD を浮かせ、**波形**を出す。波形が動いていれば「マイクは拾えている」が一目で分かる（静止＝入力デバイスか権限の異常、という自己診断を兼ねる）
- HUD には停止と**キャンセル**の両方を置く。長時間録音が丸ごと無駄になる事故を防ぐ
- HUD を丸ごと OFF にもできる。その場合も開始音・完了音で状態が分かる（音だけで完結する導線を残す）

---

## 6. コンテキストは「取りすぎない」

整形プロンプトに周辺情報（アプリ名・ウィンドウタイトル・選択テキスト・クリップボード）を載せると精度が上がる。一方で**入れすぎると出力が引きずられて品質が落ちる**。

- どの項目を使うかは `ModeContext` でモードごとに選ぶ。**既定は全部 false**
- 1 項目あたりの長さを `ContextCapture.maxFieldLength` で頭打ちにする
- **モードが要求する項目だけを取りに行く**。取得と用途が一致していないと、収集範囲を誤解させるうえ、AX の同期 IPC が録音開始を遅らせる
- ラベル（`【アプリ】` など）を必ず付ける。ラベルの無い地の文で足すと、モデルがコンテキストを整形対象と誤認して出力に混ぜる

---

## 7. 履歴は安全網

履歴は「後から読み返す機能」ではなく、**整形が事実を書き換えていないかをユーザーが自力で検証する導線**。

- 生 / 置換後 / 整形後を切り替えて見られる
- 送信プロンプトを表示できる
- 誤認識された語をその場で辞書置換に登録できる

そのうえで、残るものと消えるタイミングはユーザーの選択に従う（保存期間・すべて削除）。
録音した音声は残さない。聞き直しには一度も使われず、声は履歴の中で最も機微なデータなので削除した（Issue #4）。

---

## 8. 記号は辞書で、機械的に

「アットマーク」→ `@` のような記号入力は、LLM に任せず**決定的な文字列置換**で行う。同じ入力からは必ず同じ出力になり、数値や英単語に触れない。

同じ理由でフィラー除去（えっと・あの）も LLM を通さない。ただし**同梱の既定ルールが実在の語を壊さないこと**が前提で、これを外すと出荷時のバグになる（実際に「そのため」→「ため」、「バックスラッシュ」→「バック/」を踏んだ）。

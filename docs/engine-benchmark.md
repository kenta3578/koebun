# エンジン実測比較（2026-08-23）

音声認識2種 × 整形2種の4構成を実機で計測した記録。**この表が「どのエンジンを既定にするか」「モデルを差し替えるか」「README に何を書けるか」の判断基準**になる。エンジンやモデルを変えたら、この手順で測り直してここを上書きする。

## 計測条件

- 実機: M5 Pro / 48GB / macOS 26（Apple Intelligence 有効）
- 各構成 1回ずつ（D のみ2回）。**自然発話なので毎回まったく同じ音声ではない**。ミリ秒の差を厳密比較する精度はないが、桁の違いは十分読める
- 発話内容（数値・日付・URL・メール・意味反転しやすい表現を1文に詰めたもの）:
  > 請求額が4,217円で、期日は3月14日です。詳細は example.com/invoice を見てください。連絡先は support@example.com です。**メールをチェックする前に**振り込みをお願いします。
- 一次データ: `~/koebun/history/<timestamp>/meta.json`（`speechEngine` / `formattingEngine` / `durations` / `rawText` / `formattedText` / `diff`）

## 結果

| | 音声認識 | 整形 | 認識 | 整形 | 合計 | 整形の忠実さ |
|---|---|---|---|---|---|---|
| A | WhisperKit large-v3 | Qwen3 14B-4bit | 3,906ms | 3,766ms | 7,672ms | **生と完全一致（無改変）** |
| B | WhisperKit large-v3 | Apple 3B | 4,373ms | 1,281ms | 5,654ms | カンマ挿入・**語の脱落** |
| **C** | **Apple SpeechAnalyzer** | **Qwen3 14B-4bit** | **292ms** | **2,819ms** | **3,111ms** | **言い直しの除去のみ（仕様どおり）** |
| D | Apple SpeechAnalyzer | Apple 3B | 305 / 229ms | 2,843 / 1,432ms | 3,148ms | カンマ・空白挿入・**推測での修復** |

## 分かったこと

### 1. 音声認識は Apple が圧倒的に速い（292ms 対 3,906ms）

**13倍差。** しかも Apple は**句読点を自前で付けてくる**ので、整形の主な仕事（句読点付与・フィラー除去）の相当部分が認識側で済む。かつて他者の英語ベンチを根拠に「精度は妥協」として不採用にしていたが、**日本語の平文なら実用上の不足は無い**。

### 2. ただし Apple は英数字・URL・メールを崩す

3回とも別々の壊れ方をした:

| 正解 | Apple の出力 |
|---|---|
| `example.com/invoice` | `Excampe.comインボイス` / `。.comインボイス` / `Example.comインボイス` |
| `support@example.com` | `サポート@エxample.com` / `サポートト Example.com` / `サポートアート Exampore.com` |

WhisperKit は A で両方とも**完全に正しく**取れていた。**壊れ方が毎回違うので辞書置換では救えない**（置換は決定的なパターンにしか効かない）。

### 3. Apple の 3B 整形は禁止事項を守れない（3回中3回）

`Mode.compactRules` で「数値・URL・メールは一字一句そのまま」「内容を足さない/削らない」を指示しているが:

- **`4217円` → `4,217 円`**（B・D とも再現）。カンマと空白を挿入。**入力がきれいな B でも起きたので、壊れた入力への反応ではなく癖**
- **`3月14日` → `3 月 14 日`**
- **語の脱落**: B で `詳細はexample.comへインボイスを見てください` → `詳細はexample.comをご覧ください`。**「インボイス」が黙って消えた**
- **推測での修復**: D で `サポート@エxample.com` → `support@example.com`。今回は結果的に正解だったが、外れれば**もっともらしい嘘のアドレス**が挿入される

一方 **Qwen3 14B は3回とも生テキストを1文字も変えなかった**（C では ASR の言い直し `連絡先。先は` → `連絡先は` だけを除去。これはプロンプトが唯一許可している修正）。**指示追従の差がそのまま出た。**

### 4. 「〜する前に」の意味反転は起きなかった

`design-rationale.md` §2 の意味反転（「チェックする前に」→「チェックせずに」）は、**Qwen3・Apple 3B どちらでも再現しなかった**。ただし 3B は他の逸脱を繰り返しているので、安全とは言えない。

### 5. 整形ガードは実機で機能した

D で 3B がアドレスを推測修復したとき、`kind: email` の変化として**警告を1件出した**。狙ったところで鳴っている。

一方で**取りこぼしも分かった**:

- **数値の表記変更（`4217` → `4,217`）は警告されない。** `FormatDiff` は比較前にカンマ・空白を正規化しており（値が同じなら誤検知しないための設計）、意図どおり。ただし「記号を足すな」を守らせたいなら観測手段が無いことになる
- **語の脱落（「インボイス」）も警告されない。** 固有名詞チェックが既定 OFF のため。**削除は変更より気づきにくく害が大きい**ので、種類を問わず常に検出する案がある（未着手）

## 決定

**既定は「Apple 音声認識 + 整形なし」。ダウンロード 0・改変リスク 0 で即使える状態を出発点にする。**

整形は使いたい人が設定で有効にする:

| 整形エンジン | 追加ダウンロード | 忠実さ |
|---|---|---|
| なし（既定） | 0 | 改変なし（当然） |
| Apple Foundation Models | 0 | 上記のとおり守れない |
| Qwen3 14B-4bit | 約7.8GB | 無改変 |
| Qwen3 32B-4bit | 約18GB | 未計測 |

音声認識を**モードやアプリごとに切り替える案は却下した**。同じ言葉を喋っても場所によって結果が変わり、原因の切り分けができなくなるため。精度が要る場面は人間が設定で切り替える。

## 未検証・保留

- **Qwen3 4B / 8B**（約2.3GB / 4.5GB）。Apple 3B が守れなかったのが「サイズ」ではなく「そのモデルの指示追従」なら、Qwen3 4B は守れるかもしれない。**守れれば整形付きでも 2.3GB で済む**
- **3B 向けプロンプトの few-shot 化**（`4217円` → `4217円` の例を数個渡す）。ゼロDLで整形まで成立させたくなったら再開する
- **`FormatDiff` の削除検出の常時 ON**
- 常駐メモリの実測（今回は取っていない）
- Qwen3 32B の忠実さと速度

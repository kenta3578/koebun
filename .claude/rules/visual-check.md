# 見た目に関わる変更は描き出して目視する

描画コードを書いただけで「できた」と言わない。実機に入れる前に一度、入れた後にもう一度見る。

- **メニューバーのグリフ**（`MenuBarGlyph`）: 描画コードを scratchpad の Swift スクリプトへ写し、8 倍スケールでライト／ダーク／録音中の PNG に描き出して Read する。線画と塗りの両方を見る（別パスの重なりは線画では底辺が横切り、塗りでは抜ける）
- **実機のメニューバー**: `install-local.sh` 後に `screencapture -x -R <x,y,w,h>` で右上を撮って Read する
- **線の太さ・エッジの粗さは「幾何を拡大」して見ない。** 小さく描いてから画像を拡大すると実際より滑らかに見え、逆に幾何を拡大すると折れが消える。**Retina と同じ 2x のビットマップに実寸で描き、最近傍で拡大**して初めて画面と同じ粗さが出る（Issue #154）
- **«波» は線だけでは作れない。** 細い線を複数うねらせると «ミミズ» に見える（Issue #156）。線の下を薄く塗って面を持たせると «水面» として読める。塗りは**下へフェード**させる——べた塗りは下端が直線で切れて «四角い塊» になる。線の太さは**全部同じ**にする（違えると «別々のもの» に見える）
- **常に波打たせたいなら «時計» をマイクにする**（Issue #172）。黙っている間もうねっていてほしい、は正しい要望。ただし経過時間で動かすと速さのつまみが要り、そこから壊れる。**位相を `pushCount`（レベルが届いた回数）から決める**と、波は録音中ずっと流れるのに速さの定数が 1 つも要らない（流れる速さ＝マイクの取り込み間隔 85ms）。履歴の «山» とうねりが同じ速さで一緒に流れるので、2 つの動きに見えることもない
- **波形に «時間から決まる動き» を足さない**（Issue #170）。位相を流す・無音で脈打つ・黙ると凪ぐ・送り出しで飛ばす・レベルを平滑化する——«生きていると分かるように» のつもりで 5 つ重ね、速さのつまみが増えるだけで最後まで落ち着かなかった（#150〜#168）。音と無関係に動くものは «自分がいま何を見ているのか» が読めない。**動くのはマイクが拾った分だけ**にする（`LiveWaveformView` は位相がコマ数・振れ幅が入力レベル、`WaveformView` は高さが入力レベル。どちらも `TimelineView` を使わない）。以下 2 行はその調整で踏んだ落とし穴の記録で、**まず «そのつまみが要るのか» を疑う**
- **«速い／遅い» は静止画 1 枚では決まらない。実コマを並べる。** 0.1 秒間隔のコマ 8 枚で «忙しくないか» を、0.5 秒間隔のコマ 8 枚で «止まって見えないか» を見る。**片方の窓だけ見ると必ずどちらかに倒れる**（Issue #164 → #166。前者しか見ずに 2 回とも遅くする幅を決めきれなかった）。判定は隣り合うコマの変化量で読む
- **動きの比較コマは «無音» だけで描かない。実使用の状態も並べる。** 振幅は `max(level, 脈)` で、**喋っている間はマイクのレベル側が勝つ**。無音の行だけ描くと落ち着いて見えるので «直った» と読めてしまい、Issue #164・#166 は 2 回ともそれで空振りした（本体は 85ms ごとに届く生レベルの跳ねで、速さのつまみでは動かない → #168 で平滑化）。**どのつまみが効く状態を描いているのか**を先に確かめる
- **最小表示の波形（`LiveWaveformView`）**: `ImageRenderer` で**本物のビューを**描く（式を写すと写し間違いが混ざる）。**無音 → 喋る → 黙る を通した実コマ**を 1 枚に並べて Read する。幅に載せる履歴の長さは、短いと «幅広のこぶ»・長いと «1pt のトゲ» になるので実コマで決める（Issue #170 で 16 / 28 / 44 を比べて 28）。棒を並べる形は細いと «つぶつぶ» に見えて波にならない
- **波形（`WaveformView`。通常表示）**: **無音 / ささやき声 / 通常の発話**を 1 枚に並べて描き出して Read する。**数字だけで決めない**——`amp .14` は式の上では «波» だが、描くと 2pt の点の列と区別が付かなかった（Issue #146）。値を振った比較を先に描くと 1 往復で決まる
- **HUD**: 失敗パネル・結果パネル・警告など、変えた状態を実機で再現してスクリーンショットをもらう（HUD は `.nonactivatingPanel` なので、自分で確実に再現できない状態はユーザーに1枚頼む）
- **HUD は 5 ファイルに分かれている**（Issue #65）: `HUDLayout`（位置・サイズの定数）/ `RecordingHUDModel`（何を見せるか）/ `RecordingHUDView`（描画）/ `RecordingHUDController`（状態遷移）/ `RecordingHUDPanel`（NSPanel の生成・配置・監視）。**パネルの大きさを変えるときは `HUDMetrics` の 1 か所**で、View の frame とパネルの実サイズが必ず揃う
- **Model は `SettingsStore.shared` / `AppState.shared` を読まない。** 表示サイズと状態は Controller の `syncEnvironment()` が注入する。ここを通さずに設定を変えると**中身が変わらない**ので、表示に関わる設定を足したらこの関数も見る
- HUD は SwiftUI の `.onHover` が効かない（非アクティブのパネル）。ホバーはマウス位置とパネル枠の当たり判定で自前に取っている。ボタンを足すときは `panelSize` と frame が一致しているかも見る（ズレると見えない領域がクリックを食う）
